# Настройка на BulAdmin CRM / ERP

Системата използва същото Microsoft приложение (`cd4ae5dd-...`), същия сертификат и същия Google клиент като портала. Данните са в отделен SharePoint сайт, за да може достъпът до тях да се управлява отделно от портала.

## 0. Тайни

Частите, които не са в Git, са в `worker/.dev.vars` и `worker/.secrets/`:

```
worker/.dev.vars
  SESSION_SECRET=<нов случаен низ, поне 32 знака>
  PASSWORD_PEPPER=<нов случаен низ, поне 32 знака>
  GOOGLE_CLIENT_SECRET=<същият като в портала>
  MS_CERT_PRIVATE_KEY=<същият като в портала>
worker/.secrets/buladmin-portal.cer   (копие от портала)
```

`SESSION_SECRET` и `PASSWORD_PEPPER` трябва да са **различни** от тези на портала. Случаен низ: `node -e "console.log(crypto.randomBytes(32).toString('base64url'))"`. Без `PASSWORD_PEPPER` съществуващите пароли спират да работят, затова го пазете.

## 1. SharePoint сайт

В SharePoint admin center създайте сайт **Cloud** с адрес `/sites/cloud` (Team site без Microsoft 365 група е достатъчен). В него оставете само хора, които може да виждат всички клиентски и финансови данни: таблиците се виждат от всеки член на сайта.

Друг адрес: сменете `SP_SITE_PATH` в `worker/wrangler.toml`.

## 2. Microsoft приложение и таблици

```
cd worker
node scripts/setup-microsoft.mjs --admin ваш-имейл@bulmail.eu --name "Вашето Име"
```

Скриптът показва адрес и код. Влезте с акаунт на глобален администратор. След това той:

1. проверява сертификата и добавя `https://cloud.buladmin.eu/api/auth/microsoft/callback` към адресите за вход, без да маха тези на портала;
2. проверява `Sites.Selected` с admin consent;
3. дава на приложението достъп до сайта `cloud` (временно `manage`);
4. създава таблиците `Cloud - Контрагенти`, `Лица за контакт`, `Сделки`, `Задачи`, `Артикули`, `Търговски документи`, `Плащания`, `Потребители`, `История`, `Настройки`;
5. добавя първия администратор и отпечатва еднократен линк за парола, валиден 72 часа;
6. намалява правата върху сайта до `write`.

Скриптът може да се пуска повторно, например след добавяне на колони в `schema.json`. Изходът съдържа линка за парола, затова не го споделяйте.

## 3. Google

В Google Cloud Console → APIs & Services → Credentials → OAuth клиента на портала добавете в **Authorized redirect URIs**:

```
https://cloud.buladmin.eu/api/auth/google/callback
```

## 4. API в Cloudflare

```
cd worker
npx wrangler@4 login
npm run secrets
npm run deploy
```

Проверка: https://cloud.buladmin.eu/api/meta трябва да върне JSON. В Cloudflare DNS трябва да има запис `cloud` (CNAME към `buladmineood.github.io`) в режим **Proxied** (оранжев облак), иначе `/api/*` не стига до Worker-а.

Както при портала: хеширането на парола иска платения план Workers Paid, ако се появи грешка 1102. Добавете и правило Security → WAF → Rate limiting за `cloud.buladmin.eu/api/auth/*`.

## 5. Страници

```
cd worker
npm run stamp
```

Скриптът добавя версия към адресите на скриптовете и стиловете, за да не смесва браузърът стари и нови файлове. След това качете в `main`. GitHub Pages публикува сам; в Settings → Pages домейнът е `cloud.buladmin.eu` (файлът `CNAME`) и „Enforce HTTPS“ е включено.

## 6. Имейли (по желание)

Докато `MAIL_ENABLED = "false"`, поканите и линковете за парола се показват на администратора, за да ги изпрати сам. За автоматични имейли създайте споделена кутия `no-reply@cloud.buladmin.eu` (или сменете `MAIL_FROM`), разрешете на приложението да праща от нея със `scripts/setup-mail.ps1` от портала (с новия адрес), сложете `MAIL_ENABLED = "true"` и изпълнете `npm run deploy`.

**Никога не добавяйте `Mail.Send` на приложението в Entra:** там правото важи за всички кутии в tenant-а.

## Ежедневна работа

- **Нов потребител:** Администрация → „Потребители“ → „Поканете“. Човекът влиза с Microsoft акаунт от tenant-а или с Google акаунт с потвърден имейл, ако той съвпада с поканения. Иначе си задава парола от линка и може да свърже друг акаунт от „Профил“.
- **Роли:** Администратор (всичко, включително изтриване, анулиране на фактури и плащания), Потребител (въвежда, променя, издава), Наблюдател (само преглед и CSV).
- **Спиране на потребител:** „Деактивирайте“. Отворените сесии спират веднага. Същото става при смяна на роля.
- **Данни на фирмата:** „Настройки“. Без наименование и ЕИК системата не издава документи. Ако продължавате номерацията от друга програма, въведете „Начален номер на фактурите“ преди първата фактура.
- **Грешна фактура:** администратор я анулира (номерът не се използва повторно) или се издава кредитно известие от страницата на фактурата.
- **PDF:** „Печат / PDF“ на страницата на документа и „Запиши като PDF“ в прозореца за печат.
- **Отчети:** бутонът CSV във всеки списък дава файл, който Excel отваря с кирилица.
- **Не преименувайте** таблиците и не изтривайте колони в SharePoint: системата ги намира по тези имена. Промени в данните правете през системата, за да се пази историята и номерацията.

## Локален преглед без акаунти

```
cd worker
npm run dev
```

Отворете http://localhost:8790/. Бутоните за Microsoft и Google влизат като демо администратор. Други роли: `/dev/login?as=user` и `/dev/login?as=viewer`. Задаване на парола: `/set-password.html#t=u.dev-setup`. Данните се губят при спиране. Тестове: `npm test`.

## Ограничения, които е добре да знаете

- Всички таблици се зареждат наведнъж. Това е бързо до няколко хиляди записа в таблица; при повече ще трябва странициране на сървъра.
- Номерът на документа се проверява за дублиране след запис. Два едновременни опита за издаване получават различни номера, но при много силно натоварване е възможен отказ с молба за повторен опит.
- Вход с код по имейл за втора стъпка (както при операторите в портала) още няма. Препоръчително е Microsoft входът да е с MFA в Entra.
