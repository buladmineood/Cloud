## 0. Тайни

Частите, които не са в Git, са в `worker/.dev.vars` и `worker/.secrets/`. Създава ги:

```
powershell -ExecutionPolicy Bypass -File worker\scripts\new-certificate.ps1
```

Скриптът прави сертификата (`.secrets/buladmin-cloud.cer`), частния ключ (`MS_CERT_PRIVATE_KEY`), `SESSION_SECRET` и `PASSWORD_PEPPER` и отпечатва `MS_CERT_THUMBPRINT` за `wrangler.toml`. Съществуващи тайни не се презаписват. **Пазете `.dev.vars` на сигурно място:** без `PASSWORD_PEPPER` паролите спират да работят, а без ключа приложението не може да влезе в Microsoft. За вход с Google добавете `GOOGLE_CLIENT_SECRET` на OAuth клиента на cloud (`330949049619-gm550u…`).

## 1. SharePoint сайт

```
powershell -ExecutionPolicy Bypass -File worker\scripts\setup-site.ps1 -Owner ваш-имейл@bulmail.eu
```

Създава екипен сайт без Microsoft 365 група на адреса от `SP_SITE_PATH` и забранява външното споделяне. В сайта оставете само хора, които може да виждат всички клиентски и финансови данни.

## 2. Microsoft приложение, домейн и таблици

```
cd worker
node scripts/setup-microsoft.mjs --admin ваш-имейл@bulmail.eu --name "Вашето Име"
```

Скриптът показва адрес и код. Влезте с акаунт на глобален администратор. След това той:

1. създава (или намира) приложението „BULADMIN Cloud“ със сертификата и адреса `https://cloud.buladmin.eu/api/auth/microsoft/callback` и записва Application ID в `wrangler.toml`;
2. одобрява входа (`openid email profile`) и правата за SharePoint за цялата организация: Graph `Sites.Manage.All` (таблиците във всички сайтове на cloud) и SharePoint `Sites.FullControl.All` (системата сама създава отделен сайт за всяка нова фирма). Тези права важат за целия SharePoint на tenant-а — затова частният ключ на сертификата (`.dev.vars`, тайната в Cloudflare) трябва да се пази строго;
3. проверява домейна `cloud.buladmin.eu` в tenant-а и отпечатва нужните DNS записи;
4. дава на приложението достъп до сайта (временно `manage`);
5. създава таблиците `Cloud - Контрагенти`, `Лица за контакт`, `Сделки`, `Задачи`, `Артикули`, `Търговски документи`, `Плащания`, `Потребители`, `История`, `Настройки`;
6. добавя първия администратор и отпечатва еднократен линк за парола (72 часа; не е нужен при вход с Microsoft);
7. намалява правата върху сайта до `write`.

Скриптът може да се пуска повторно, например след добавяне на колони в `schema.json`: новите колони се добавят и в сайтовете на всички фирми. Приложението на портала не се променя.

### Отделна база данни за всяка фирма

Всяка нова фирма получава собствен SharePoint сайт `/sites/cloud-<id>` (без Microsoft 365 група и без външно споделяне) със своите таблици, история и лого. Сайтът се създава до около минута след регистрацията; дотогава потребителят вижда „Подготвяме базата данни“. Ако SharePoint върне грешка, администраторите на БУЛАДМИН получават имейл, а в „Организации“ → фирмата → „База данни“ има бутон „Подгответе базата отново“. Сутрешният Cron също довършва незавършените сайтове.

В общия сайт `cloud` остават профилите, фирмите, членствата, плановете и историята на тези записи.

Фирмите, регистрирани преди отделните сайтове, работят с общия сайт („База данни: Обща“), докато не се преместят:

```
cd worker
node scripts/migrate-org-sites.mjs          # показва какво ще се премести
node scripts/migrate-org-sites.mjs --run    # премества (по желание --org ORG-XXXX)
```

По време на преместването фирмата показва „Подготвяме базата данни“. Старите записи в общия сайт не се изтриват — остават като резервно копие и могат да се изтрият ръчно, след като проверите новия сайт.

Проверка с истинските данни: `node scripts/check-microsoft.mjs --mail ваш-имейл@bulmail.eu` чете таблиците и праща пробен имейл.

## 4. API в Cloudflare

```
cd worker
npx wrangler@4 login
npm run secrets
npm run deploy
```

Проверка: https://cloud.buladmin.eu/api/meta трябва да върне JSON. В Cloudflare DNS трябва да има запис `cloud` (CNAME към `buladmineood.github.io`) в режим **Proxied** (оранжев облак), иначе `/api/*` не стига до Worker-а.

Както при портала: хеширането на парола иска платения план Workers Paid, ако се появи грешка 1102. Добавете и правило Security → WAF → Rate limiting за `cloud.buladmin.eu/api/auth/*`.

## 5. Страници

```
cd worker
npm run stamp
```

Скриптът добавя версия към адресите на скриптовете и стиловете, за да не смесва браузърът стари и нови файлове. След това качете в `main`. GitHub Pages публикува сам; в Settings → Pages домейнът е `cloud.buladmin.eu` (файлът `CNAME`) и „Enforce HTTPS“ е включено.

## 6. Имейли

Поканите, линковете за парола и „Забравена парола?“ идват от `no-reply@cloud.buladmin.eu` (`MAIL_ENABLED = "true"`). Настройката е с Exchange администратор:

```
powershell -ExecutionPolicy Bypass -File worker\scripts\setup-mail.ps1
```

Скриптът създава споделената кутия, разрешава на приложението да праща **само от нея** през Exchange RBAC и включва DKIM. Накрая `InScope` трябва да е `True` за no-reply и `False` за Вашата кутия. DNS записите на домейна (MX, SPF, двата DKIM CNAME) вече са в Cloudflare. По желание добавете и DMARC: `TXT _dmarc.cloud.buladmin.eu "v=DMARC1; p=quarantine; rua=mailto:dmarc@buladmin.eu"`.

**Никога не добавяйте `Mail.Send` на приложението в Entra:** там правото важи за всички кутии в tenant-а.


### Обявления от ЦАИС ЕОП

Вносът **не минава през Cloudflare Worker-а**. Пуска го GitHub Actions ([.github/workflows/eop-import.yml](../.github/workflows/eop-import.yml)) всеки ден в 07:00 UTC (09:00 или 10:00 българско време) със скрипта `worker/scripts/eop-import.mjs`. Данните са отворените данни на АОП (OCDS, CC0), по един файл за ден, от два източника:

1. **ЦАИС ЕОП → Отворени данни** (https://app.eop.bg/today/reporting/open-data). Това е основният източник. Файлът за деня е на постоянен адрес в `storage.eop.bg` и излиза около 08:00 на следващата сутрин.
2. **Портал за отворени данни** (data.egov.bg, Агенция по обществени поръчки, организация 502). Това е резервният източник: ползва се, ако файлът в ЦАИС ЕОП липсва или сървърът не отговаря. Там същите данни понякога закъсняват със седмици.

Ден, който липсва и в двата източника, се чака 3 дни, после се пропуска, за да не спре вносът. Скриптът пише направо в SharePoint през Microsoft Graph:

- файла `ЦАИС ЕОП/обявления.json` в библиотеката „Документи“ на общия сайт (само откритите поръчки; изтеклите и възложените се махат);
- следените поръчки в сайтовете на фирмите (нов срок, класиране, договор, прекратяване) и имейлите по CPV.

Worker-ът само чете файла (кеш до 30 минути), за да покаже страницата „Обявления в ЦАИС ЕОП“.

Еднократна настройка в GitHub: **Settings → Secrets and variables → Actions → New repository secret**, име `MS_CERT_PRIVATE_KEY`, стойността от `worker/.dev.vars`. Ръчно пускане: **Actions → ЦАИС ЕОП внос → Run workflow**.

От компютър (същото, напр. за наваксване):

```
cd worker
node scripts/eop-import.mjs --dry   # колко дни чакат
node scripts/eop-import.mjs
```

Локално: `DEV_EOP=1 npm run dev` зарежда истинските обявления в демо сървъра.

## Ежедневна работа

### Администратори на БУЛАДМИН („БУЛАДМИН“ в менюто)

- **Спряна или неплатена фирма е само за преглед:** хората в нея виждат и изтеглят данните си (PDF, CSV), но не могат да създават, променят или изпращат. Над всяка страница стои жълто съобщение с причината.
- **Организации:** списък на всички регистрирани фирми с план, администратори, използване за месеца и състояние на базата данни. Филтърът „Чакат плащане“ показва фирмите за активиране. В страницата на фирмата: смяна на плана, „Платен до“, статус (Активна, Чака плащане, Спряна), „Само с платен план“, бележки, добавяне на хора (без ограничението на плана) и „Влезте като администратор“.
- **Втора фирма в профил:** идва със статус „Чака плащане“ и избрания план; получавате имейл. Изпратете проформа и след плащането задайте статус „Активна“ и „Платен до“. След тази дата фирмата пак чака плащане (не минава на безплатния план). Първата фирма в профил след „Платен до“ минава на безплатния план.
- **Планове:** ограниченията и дали логото е включено. Празно поле означава „без ограничение“. Промяната важи веднага за всички фирми на плана. Цената е само за сведение: плащанията засега се уреждат извън системата.
- **Всички потребители:** линк за парола, блокиране на профил и даване или отнемане на правата на администратор на БУЛАДМИН.
- При всяка нова регистрация на фирма администраторите на БУЛАДМИН получават имейл.

### Администратори на фирма

- **Нов колега:** „Потребители“ → „Поканете“. Ако човекът вече има профил, фирмата се появява в неговото меню; иначе получава линк за парола. Броят хора е ограничен от плана.
- **Роли:** Администратор (всичко, включително хора, настройки, лого, изтриване, анулиране на фактури и плащания), Потребител (въвежда, променя, издава), Наблюдател (само преглед и CSV). В организацията винаги остава поне един администратор.
- **Спиране на достъп:** „Спрете достъпа“ маха човека само от тази фирма; профилът и другите му фирми остават.
- **Данни на фирмата, лого и план:** „Настройки и план“. Без наименование и ЕИК системата не издава документи. Логото е PNG или JPG до 300 KB и се показва само при план с лого.
- **Грешна фактура:** администратор я анулира (номерът не се използва повторно) или се издава кредитно известие.
- **PDF:** бутонът „Изтеглете PDF“ на страницата на документа. PDF-ът не се пази в SharePoint, а се създава наново всеки път от записаните данни, затова е един и същ. Печатът от браузъра е изключен.
- **Отчети:** бутонът CSV във всеки списък дава файл, който Excel отваря с кирилица.
- **Не преименувайте** таблиците и не изтривайте колони в SharePoint: системата ги намира по тези имена. Промени в данните правете през системата, за да се пазят историята, номерацията и разделението между фирмите.

## Локален преглед без акаунти

```
cd worker
npm run dev
```

Отворете http://localhost:8790/. Бутоните за Microsoft и Google влизат като демо администратор на БУЛАДМИН, който е в две фирми (на „Стандартен“ и на „Безплатен“ план). Други роли: `/dev/login?as=user` и `/dev/login?as=viewer`. Задаване на парола: `/set-password.html#t=u.dev-setup`. Данните се губят при спиране. Тестове: `npm test`.

## Ограничения, които е добре да знаете

- Данните на една фирма се зареждат наведнъж. Това е бързо до няколко хиляди записа на фирма; при повече ще трябва странициране на сървъра.
- Данните на всяка фирма са в отделен сайт. Членовете на общия сайт `cloud` виждат профилите и списъка с фирми, затова в него трябва да са само администратори на БУЛАДМИН. Хората от фирмите влизат само през системата; не ги добавяйте директно в SharePoint сайтовете.
- Номерът на документа се проверява за дублиране след запис. При много силно натоварване е възможен отказ с молба за повторен опит.
- Плащането на плановете не е автоматично: администратор на БУЛАДМИН сменя плана и срока му ръчно.
- Вход с код по имейл за втора стъпка още няма. Препоръчително е Microsoft входът да е с MFA в Entra.
